* Synopsis
:PROPERTIES:
:CUSTOM_ID: summary
:END:
** Outcome
- An *operator creates an open poll* using the Exodan-style admin CLI and receives a share URL.
** Before
- The project has *documentation only*, without a deployable service or poll store.
** After
- A *single TSV event log per UUID-named poll* is authoritative for its title, options and state.
- The CLI *creates and inspects* polls without a public administration route.
** Changes
- Introduce the *Go binary*, runtime configuration, operator commands, read-only poll display and state-store foundation.
** Unchanged
- *Exodan owns* deployment, service identity, wrapper authorization and TLS; ballot submission and counting belong to later work.
** Edge cases
:PROPERTIES:
:CUSTOM_ID: synopsis-edge-cases
:END:
- *Invalid input or interrupted creation* cannot publish a partial poll; corrupt state fails closed.
** Decisions
- *One physical TSV line per event* with JSON payload; *no separate state database*.
** Next step
- Definition review and operator sign-off precede implementation.

* Context
:PROPERTIES:
:CUSTOM_ID: context
:END:
** Problem
- The MVP needs poll creation without building creator login, mail or browser administration.
** Outcome
- An authorized host operator can create an open poll with initial choices and obtain its URL; a voter can read that poll.
** Scope
*** In scope
- Go executable, local build/test/lint/vulncheck entry points, Exodan-compatible configuration, event-store library, create/show CLI, public read-only ballot page.
*** Out of scope
- Ballot submission, duplicate deterrence, close/count/results, option edits, browser administration, mail, deployment execution.
*** Unchanged
- Exodan provides the =APP-admin= wrapper, operator authorization, host identity, bind address and reverse proxy.
** Authority and starting point
- Project profile :: [[file:../../.sdlc/project.yaml][Project SDLC profile]]
- Product authority :: [[file:../../docs/MVP.md][MVP scope]], [[file:../../docs/VISION.md][Vision]]
- Architecture authority :: [[file:../../docs/ARCHITECTURE.md][Proposed architecture]]
- External contract :: Exodan =deploy/docs/PROJECT-INTEGRATION.md=, sections on the admin wrapper, runtime, config and data directories (read-only authority).
- Implementation :: No existing application code or regression suite.
** Constraints and dependencies
:PROPERTIES:
:CUSTOM_ID: constraints-and-dependencies
:END:
- Use =STATE_DIRECTORY/polls/<uuid>/events.tsv= with UTF-8 records and JSON payload; no direct writes outside app state.
- Supply =config/defaults.yaml= with =base_url= and =data_dirs: [templates, static]=; deployment-specific =config/<host>.yaml= is required when a host is selected, not invented for an unknown target.
- Bound poll creation to 2–200 options, a 200-character title, 200-character option names and 2,000-character descriptions; trim surrounding whitespace and reject empty or duplicate normalized names.
- Serve bundled =templates/= and =static/= from the app working directory declared in =data_dirs=. No email or Node.js/npm dependency.
- This work must land before ballot and close/count tickets; those consume its reader, writer and CLI entry point.
** Decisions
- A newly created poll is *open immediately* and its options cannot change in the MVP.
- Store format version, monotonic sequence, UTC timestamp, event type and JSON payload per line; event replay rejects gaps and malformed complete records.
** Unresolved blockers
- None for definition; the target deployment host and domain are operator-selected at deployment, not guessed here.

- Condition :: Process exits while the initial poll record is being written.
- Required behaviour :: Poll is not published and its directory is not treated as a valid poll; subsequent creation can use another UUID.

* Solution Design
:PROPERTIES:
:CUSTOM_ID: solution-design
:END:
** Architecture context
- Relevant components :: New binary, per-poll event store, HTTP renderer; [[file:../../docs/ARCHITECTURE.md][proposed architecture]].
- Ownership boundary :: Application owns validation and event state; Exodan owns deployment and operator wrapper.
** High-level design
*** Components and responsibilities
- A shared store validates UUID poll paths, serializes and persists complete events, then replays them to a read model. CLI and HTTP consume that same read model.
- CLI create accepts title and repeated options, with an input file for multiline descriptions using a documented structured format; prints the canonical URL only after durable creation. CLI show reads state without mutation.
- HTTP GET uses =html/template= escaping; serving bind is =ADDR=, config comes from =DEFAULT_CONFIG_PATH= and =CONFIG_PATH=, mutable data from =STATE_DIRECTORY=.
*** Interfaces and configuration
- CLI contract :: =democrac create --title TITLE --option NAME [--option NAME ...]= for simple names; =--input FILE= is a UTF-8 YAML document with =title= and =options= (each =name= and optional =description=). Exactly one mode per invocation. =democrac show POLL_UUID= displays the canonical share URL and poll state. Binary also provides =serve=.
- Runtime :: Config =base_url= is absolute HTTPS in production, localhost HTTP in local tests. The application reads =base_url=; Exodan-owned =data_dirs=, =extra_domains=, =timers=, =service= and legacy =exec_args= may coexist in those YAML files but are not application settings. Reject other unrecognized top-level keys and invalid structures for known keys; do not reinterpret Exodan-owned fields. =ADDR= is mandatory in service mode; the CLI requires state and configuration, not =ADDR=.
- Event record :: =version<TAB>sequence<TAB>timestamp<TAB>type<TAB>payload_json<LF>=. Version begins at 1. A JSON encoder escapes literal tabs and newlines; parsing checks exact column count, type and monotonic sequence. Creation is one event containing title and the ordered options with stable IDs, so an incomplete creation is never published.
*** Failure behaviour
- Write each complete event with an exclusive per-poll lock and confirm durability before success. Creation writes to a new UUID directory privately and publishes it atomically by renaming into =polls/= only once the initial record and directory are durable; readers ignore unpublished staging directories. Review must confirm this publish boundary. A trailing incomplete record blocks subsequent writes and reads that would present a valid result. Recovery means an operator retains the damaged directory for forensic inspection and restores a valid backup or creates a new poll; no automatic truncation or repair of the append-only log is allowed.
*** Simplicity and proportionality
- One Go binary and one event log per poll avoid a relational store and dual-write audit. No mail, host script or browser admin.
** Design decisions and verification
*** Single authoritative history
- Decision :: The event stream is the sole poll authority, with derived read models only.
- Verification :: [[#rt-001-3][RT001.3 - Replay and reject corrupt history]]; implementation review checks that no second mutable state source is introduced.
** Architecture impact
*** Security impact
- Threat boundary :: Public HTTP can only read polls; CLI mutation is restricted by host operator wrapper.
- Data and secrets :: User-entered labels and descriptions are untrusted; do not log raw values. Private poll files are accessible to app identity, not directly served as static files.
- Access :: No HTTP mutation endpoints for creation/closure. Generated IDs are validated before filesystem lookup to prevent traversal.
- Conclusion :: Fail closed on invalid state; HTML-escape display fields and keep admin mutation outside HTTP.
